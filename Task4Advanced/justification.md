# Обоснование перехода на событийно-ориентированную архитектуру

## Проблемы текущей архитектуры

В текущей системе компании «Будущее 2.0» используется централизованный DWH и интеграционная шина Apache Camel. Такой подход создаёт ряд ограничений.

### Централизованный DWH

Вся аналитическая логика и данные сосредоточены в одном хранилище.  
Это приводит к следующим проблемам:

- высокая связанность систем
- сложность внесения изменений
- длительное формирование отчётов
- ограниченные возможности масштабирования

### Интеграция через Apache Camel

Camel используется как ESB для интеграции сервисов.  
Однако большинство интеграций построено синхронно и требует изменения маршрутов при подключении новых систем.

Это приводит к:

- усложнению поддержки
- зависимостям между сервисами
- увеличению времени внедрения изменений

---

## Преимущества событийной архитектуры

### Слабая связанность

Сервисы взаимодействуют через события, а не через прямые вызовы.  
Это позволяет доменам развиваться независимо.

Новые сервисы могут подключаться к событиям без изменения существующих систем.

### Масштабируемость

Событийный брокер (Kafka) позволяет масштабировать обработку событий горизонтально.

Каждый сервис может обрабатывать события независимо.

### Реактивность системы

События публикуются сразу после изменения состояния системы.

Например:
- AppointmentCompleted



может автоматически инициировать:

- создание счёта
- обновление статистики
- запуск анализа данных

### Надёжность

События сохраняются в журнале брокера.

Это позволяет:

- повторно воспроизводить события
- проводить аудит операций
- анализировать историю изменений

### Интеграция новых бизнес-направлений

При подключении новых партнёров (фармацевтические компании, производители оборудования) новые системы могут просто публиковать события в брокер.

Это исключает необходимость изменять существующие интеграции.

---

## Сравнение подходов

| Критерий | Legacy архитектура | Event Driven архитектура |
|---------|------------------|--------------------------|
| Связанность | Высокая | Низкая |
| Масштабируемость | Ограничена | Горизонтальная |
| Актуальность данных | Batch | Near real-time |
| Time-to-market | Медленный | Быстрый |
| Интеграция новых систем | Сложная | Простая |

---

## Вывод

Переход на событийную архитектуру является необходимым шагом для реализации стратегических целей компании:

- масштабирование бизнеса
- интеграция новых направлений
- развитие аналитики
- обработка данных в режиме near real-time
